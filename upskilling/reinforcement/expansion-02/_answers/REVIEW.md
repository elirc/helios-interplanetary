# Sealed capstone and review notes

Reject aggregate balance checks that omit journal identity or organization. Check amount units, serialization, and exactness before debating performance. Do not use the learning model as a reason to migrate an existing amount representation without a separate compatibility decision.

For telemetry, require a bounded route label and independent error-path evidence. A unit test of grouping cannot prove a 401/500 was instrumented correctly. Averages and empty windows need honest labels. The learner should identify which existing integration test or fixture can verify the next boundary without resetting the development review world.

## Assess a learner's explanation

Ask for the actual input and observable result, then change one assumption. A strong explanation adapts the test or identifies a missing product decision. A weak explanation repeats the reference implementation without explaining why its boundary belongs there.

Do not award runtime evidence for a written plan. Keep “source supports this,” “model reproduced this,” and “application reproduced this” as separate statements. If an existing implementation already handles a scenario, the useful contribution may be a test and a clearer contract rather than another fix.
